# 영상 제작 로드맵

> **현재 위치: Phase 1 · 1-1 프로젝트 브리프**
>
> 진행 규칙
> 1. 한 번에 한 스텝만 진행한다. 스텝의 산출물이 나오면 체크하고 다음 스텝으로 간다.
> 2. 각 Phase 끝의 **Gate(통과 기준)** 를 모두 만족해야 다음 Phase로 넘어간다.
> 3. 앞 단계 문서를 바꾸면 그 문서를 참조하는 뒷 단계 문서에 `⚠ 재검토` 표시를 붙인다.
> 4. 도구(스킬/플러그인/MCP)는 **해당 Phase에 들어갈 때만** 켠다. 미리 다 켜두면 컨텍스트를 차지하고 권한 요청만 늘어난다.

## 0. 순서를 이렇게 잡은 이유

### "글로벌 CSS 먼저? 스토리 먼저?"

**정답: 기술 사양 → 컨셉·스토리 → 스타일(글로벌 CSS) 순서.**

영상 제작에는 웹 개발의 두 가지 "전역 설정"에 해당하는 것이 따로 있다.

| 웹 개발 | 영상 제작 | 언제 정하나 |
|---|---|---|
| `next.config`, 빌드 타깃 | **기술 사양**: 길이, 화면비(16:9 / 9:16), 해상도, fps, 플랫폼, 제작 방식 | **가장 먼저 (Phase 1)**. 바꾸면 구도·자막 위치·컷 수가 전부 다시 계산된다. |
| `globals.css`, 디자인 토큰 | **비주얼 바이블**: 풍, 컬러, 조명, 렌즈, 구도 규칙, 모션 언어, 프롬프트 토큰 | **스토리 뒤 (Phase 3)**. 스타일은 스토리를 표현하는 수단이다. |

스타일을 스토리보다 먼저 확정하면 생기는 문제:

- **컬러 스크립트를 못 만든다.** 씬마다 감정이 다르면 색도 달라져야 하는데(예: 갈등 씬은 차갑게, 해소 씬은 따뜻하게), 감정 곡선은 스토리가 있어야 나온다.
- **구도·모션 규칙이 근거를 잃는다.** "클로즈업을 언제 쓰나", "카메라를 언제 움직이나"는 장면의 의미에서 나온다.
- **캐릭터 외형이 스토리와 어긋난다.** 성격과 역할이 정해지기 전에 정한 외형은 나중에 거의 다 수정하게 된다.

예외로 **풍의 큰 방향**(실사 / 2D / 3D / 혼합)은 Phase 1에서 1차로 정한다. AI 이미지·영상 생성으로 만들 수 있는 것과 없는 것이 이 방향에 따라 달라지고, 그 한계가 스토리 작성 범위를 정하기 때문이다. HEX 값, 렌즈 mm, 이징 같은 세부 값은 Phase 3에서 정한다.

### 영상 제작의 진짜 "글로벌 CSS" = 프롬프트 토큰 시스템 (3-8)

AI로 이미지·영상을 만들 때 일관성을 지키는 방법은 **같은 문장 조각을 모든 프롬프트에 똑같이 넣는 것**이다.
CSS 변수처럼 `STYLE_BASE`, `CHR-01`, `LOC-02` 같은 토큰을 한 번 정의하고, 모든 샷 프롬프트는 이 토큰을 조합해서만 만든다.
그래서 Phase 3의 3-8을 가장 공들여 만들어야 한다.

### "하나씩 만들어 합치는" 방식을 위한 ID 체계

모든 조각에 ID를 붙여 문서끼리 서로 참조하게 한다. 그래야 나중에 합칠 수 있다.

| 접두사 | 대상 | 예시 |
|---|---|---|
| `CHR-` | 캐릭터 | `CHR-01` |
| `LOC-` | 배경/장소 | `LOC-03` |
| `PRP-` | 소품 | `PRP-02` |
| `SC-` | 씬 | `SC-04` |
| `SH-` | 샷 (씬-샷 번호) | `SH-04-02` |
| 파일명 | 생성 결과물 | `SH-04-02_key_v03.png`, `SH-04-02_take02.mp4` |

### Phase를 이렇게 나눈 이유 (도구 기준)

| Phase | 작업 성격 | 주로 쓰는 도구 |
|---|---|---|
| 1. 기획·사양 | 결정과 리서치 | 브레인스토밍, 리서치 |
| 2. 스토리·캐릭터·배경 | 글쓰기, 구조 설계 | 브레인스토밍, FigJam 다이어그램 |
| 3. 비주얼·모션 바이블 + 샷 설계 | 디자인 시스템, 시각 기획 | Figma, 디자인 시스템 스킬, 프롬프트 가이드 |
| 4. 이미지 생성 | 생성형 AI (이미지) | 이미지 생성 플러그인/MCP |
| 5. 영상 제작·후반 | 생성형 AI (영상), 편집, 오디오 | 영상 생성 MCP, Remotion, 편집 MCP |

Phase 1~3은 문서 작업이고, Phase 4부터 생성 작업이다. 문서 단계에서 결정을 끝내 둘수록 생성 비용(크레딧)과 재작업이 줄어든다.

## 폴더 구조

각 스텝에 들어갈 때 해당 파일을 만든다. 미리 만들지 않는다.

```
video/
├── ROADMAP.md              ← 이 문서 (진행 상황 기록)
├── 01_brief/               Phase 1
├── 02_story/               Phase 2
├── 03_bible/               Phase 3
├── 04_images/              Phase 4  (생성 이미지 + prompt-log)
└── 05_video/               Phase 5  (클립, 오디오, 편집 프로젝트, 최종본)
```

> 대용량 바이너리(이미지·영상)를 git에 바로 올릴지, Git LFS나 외부 저장소를 쓸지는 Phase 4-0에서 정한다.

## Phase 1. 기획 · 기술 사양 (문서)

**목표:** "무엇을, 누구에게, 어떤 규격으로" 만드는지 확정한다.

- [ ] **1-1 프로젝트 브리프** → `01_brief/brief.md`
  - 영상의 목적 (왜 만드는가, 보고 나서 시청자가 무엇을 느끼거나 해야 하는가)
  - 타깃 시청자 (누가, 어떤 상황에서 보는가)
  - 배포 채널 (포트폴리오 사이트, YouTube, Reels/Shorts 등)
  - 성공 기준 (무엇이 되면 "잘 만들었다"고 판단하는가)
  - 제약 (마감일, 예산·크레딧, 사용 가능 시간)
- [ ] **1-2 기술 사양** → `01_brief/tech-spec.md`
  - 총 길이(초), 화면비, 해상도, fps
  - 컷 수 예산 (총 길이 ÷ 평균 샷 길이)
  - 제작 방식: AI 이미지 → 이미지-투-비디오 / Remotion 모션그래픽 / 혼합
  - 언어, 내레이션 여부, 자막 여부
  - 플랫폼 세이프존 (9:16이면 상하단 UI 영역)
- [ ] **1-3 컨셉 정의** → `01_brief/concept.md`
  - 로그라인 1문장 ("[누가] [무엇을 원해서] [무엇을 하는데] [무엇이 막는다]")
  - 핵심 메시지 1문장
  - 톤 키워드 3~5개 (예: 고요한, 따뜻한, 미래적인)
  - 장르와 형식 (내러티브 / 브랜드 필름 / 모션그래픽 / 뮤직비디오 등)
  - **하지 않을 것** 목록 (피할 톤, 클리셰, 표현)
- [ ] **1-4 레퍼런스 리서치** → `01_brief/references.md`
  - 레퍼런스 영상·이미지 5~10개
  - 각 레퍼런스에서 **무엇을** 가져올지 한 줄씩 (색 / 컷 리듬 / 카메라 / 조명 / 타이포)
  - 가져오지 않을 점도 같이 적는다
- [ ] **1-5 풍의 큰 방향 결정** → `01_brief/concept.md`에 추가
  - 실사 / 2D 일러스트 / 3D / 혼합 중 선택
  - 시대감, 현실성 수준 (사실적 ↔ 양식화)
  - 이 방향에서 AI 생성으로 어려운 것 (손, 글자, 일관된 얼굴 등)과 그 대책

**Phase 1 Gate**
- [ ] 로그라인 한 문장만으로 다른 사람에게 영상을 설명할 수 있다
- [ ] 기술 사양이 확정되었다 (이후 변경하면 Phase 2~5 전체를 다시 검토)
- [ ] 레퍼런스마다 "가져올 것"이 적혀 있다

**도구**
| 종류 | 이름 | 용도 | 상태 |
|---|---|---|---|
| 스킬 | `superpowers:brainstorming` | 질문을 하나씩 주고받으며 목적·컨셉 구체화 | 사용 가능 |
| 스킬 | `anthropic-skills:deep-research` | 레퍼런스·트렌드 조사 | 사용 가능 |
| 도구 | WebSearch | 레퍼런스 검색 | 사용 가능 |
| MCP | Notion (선택) | 문서를 Notion에서도 보고 싶을 때 동기화 | 연결됨 |

## Phase 2. 스토리 · 캐릭터 · 배경 (문서)

**목표:** 영상의 내용과 등장 요소를 텍스트로 전부 확정한다.

- [ ] **2-1 시놉시스** → `02_story/synopsis.md`
  - 3~5문단으로 처음부터 끝까지
- [ ] **2-2 구조 · 비트 시트** → `02_story/beats.md`
  - 3막 또는 기승전결
  - 비트마다 **초 단위 시간 배분**. 합계가 1-2의 총 길이와 맞아야 한다
  - 오프닝 3초 훅 (특히 숏폼이라면 필수)
- [ ] **2-3 캐릭터 바이블** → `02_story/characters.md`
  - `CHR-ID`, 이름, 역할, 성격, 목표, 변화(아크)
  - 외형을 **고정 요소**(얼굴형, 헤어, 체형, 시그니처 의상·색·소품)와 **변동 요소**(표정, 포즈, 씬별 의상)로 나눈다
  - 고정 요소는 Phase 3-8에서 프롬프트 토큰이 된다
- [ ] **2-4 배경 · 세계관 바이블** → `02_story/locations.md`
  - `LOC-ID`, 장소 설명, 시간대, 날씨, 핵심 소품(`PRP-ID`), 분위기
  - 장소끼리의 공간 관계 (동선이 이어지는 경우)
- [ ] **2-5 스크립트** → `02_story/script.md`
  - `SC-ID`별: 장소(`LOC`), 등장(`CHR`), 액션, 대사·내레이션, 자막 문구
  - 내레이션은 소리 내 읽어 시간을 잰다
- [ ] **2-6 감정 곡선** → `02_story/emotion-curve.md`
  - 씬별 감정과 강도(1~10)
  - Phase 3-2 컬러 스크립트와 3-5 모션 강도의 근거가 된다

**Phase 2 Gate**
- [ ] 스크립트 낭독 시간이 목표 길이 ±10% 안에 든다
- [ ] 모든 씬이 `CHR-` / `LOC-` ID를 참조하고, 정의되지 않은 ID가 없다
- [ ] 각 캐릭터의 고정 외형 요소가 문장으로 적혀 있다

**도구**
| 종류 | 이름 | 용도 | 상태 |
|---|---|---|---|
| 스킬 | `superpowers:brainstorming` | 캐릭터·플롯 아이디어 발전 | 사용 가능 |
| MCP | Figma (FigJam `generate_diagram`) | 비트 구조도, 캐릭터 관계도, 장소 동선도 | 연결됨 |
| 스킬 | `skill-creator` (선택) | "ID 참조 무결성 검사" 같은 반복 검수를 프로젝트 스킬로 만들기 | 사용 가능 |

## Phase 3. 비주얼 · 모션 바이블 + 샷 설계 (문서) — "글로벌 CSS"

**목표:** 모든 이미지·영상 생성에 공통으로 적용할 규칙과, 샷 단위 설계도를 만든다.

- [ ] **3-1 아트 스타일 (풍)** → `03_bible/style.md`
  - 렌더링 방식, 선·질감, 디테일 수준, 참고 작가·매체
  - 금지 요소 (네거티브 프롬프트 후보)
- [ ] **3-2 컬러 시스템** → `03_bible/color.md`
  - 메인 / 서브 / 액센트 HEX
  - 씬별 **컬러 스크립트** (2-6 감정 곡선 기반)
  - 캐릭터 시그니처 컬러
- [ ] **3-3 조명 · 렌즈 규칙** → `03_bible/lighting-lens.md`
  - 키 라이트 방향, 명암 대비, 시간대별 조명
  - 기본 렌즈(mm), 피사계 심도, 필름 그레인 여부
- [ ] **3-4 구도 규칙** → `03_bible/composition.md`
  - 샷 사이즈 정의 (ECU / CU / MS / WS / EWS)와 각각 언제 쓰는지
  - 앵글 (아이레벨, 로우, 하이, 버드아이)의 의미 부여
  - 3분할·중앙 배치 규칙, 180도 규칙, 시선 방향
  - 자막·플랫폼 UI 세이프존
- [ ] **3-5 모션 언어** → `03_bible/motion.md`
  - 카메라 무브 어휘 (고정, 푸시인, 풀아웃, 팬, 틸트, 돌리, 오빗, 핸드헬드)와 각각의 의미
  - 속도·이징 규칙, 감정 강도에 따른 움직임 크기
  - 전환 규칙 (컷, 디졸브, 매치컷, 휩팬)
  - 평균 샷 길이와 컷 리듬
- [ ] **3-6 타이포 · 그래픽** → `03_bible/typography.md`
  - 자막·타이틀 폰트, 크기, 위치, 등장 애니메이션
- [ ] **3-7 사운드 방향** → `03_bible/sound.md`
  - BGM 장르·BPM, 효과음 톤, 내레이션 목소리 톤
- [ ] **3-8 프롬프트 토큰 시스템 ★** → `03_bible/prompt-tokens.md`
  - `STYLE_BASE`: 모든 프롬프트 앞에 붙는 스타일 문장
  - `CHR-xx`: 캐릭터 고정 외형 문장 (2-3에서 가져옴)
  - `LOC-xx`: 장소 문장 (2-4에서 가져옴)
  - `LIGHT-xx`, `CAM-xx`: 조명·카메라 프리셋
  - `NEGATIVE`: 공통 네거티브
  - 조립 공식: `STYLE_BASE + SHOT(사이즈·앵글) + CHR + 액션 + LOC + LIGHT + CAM`
- [ ] **3-9 샷 리스트** → `03_bible/shot-list.md`
  - 표: `SH-ID` | 씬 | 길이(초) | 샷 사이즈 | 앵글 | 카메라 무브 | CHR | LOC | 액션 | 대사·자막 | 전환
- [ ] **3-10 텍스트 스토리보드** → `03_bible/storyboard.md`
  - 샷마다 시작 프레임과 끝 프레임 묘사 (이미지-투-비디오의 입력이 된다)
  - 샷마다 토큰으로 조립한 **완성 프롬프트**

**Phase 3 Gate**
- [ ] 샷 리스트의 길이 합이 목표 길이와 맞다
- [ ] 모든 샷 프롬프트가 토큰 조합만으로 만들어진다 (샷마다 즉흥으로 쓴 스타일 문구가 없다)
- [ ] 컬러·모션 규칙이 감정 곡선과 연결되어 있다

**도구**
| 종류 | 이름 | 용도 | 상태 |
|---|---|---|---|
| MCP | Figma | 무드보드, 컬러 팔레트, 스타일 프레임 레이아웃, FigJam 스토리보드 | 연결됨 |

## 도구 운영 메모

- **설치 위치:** 플러그인과 커넥터(MCP)는 claude.ai 설정에서 켠다. 켠 뒤 새 세션에서 반영된다.
- **네트워크:** 이 클라우드 환경은 허용된 호스트만 접속된다. 외부 생성 서비스(Creative Claw 등)의 MCP가 연결되지 않으면 해당 Phase 진입 시 환경 네트워크 허용 목록에 그 호스트를 추가해야 한다.
- **비용:** Phase 4·5 도구는 대부분 크레딧 기반이다. 4-0, 5-0의 모델 비교 테스트를 건너뛰지 않는 것이 결과적으로 크레딧을 아낀다.
- **보안:** API 키를 문서나 코드에 쓰지 않는다. 필요하면 환경의 시크릿 기능으로 넣는다.
